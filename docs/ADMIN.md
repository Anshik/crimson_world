# Администрирование игроков

Дата: 16 октября 2026 года. Статус: развёрнуто на сервере в сборке `db4bb4cf83a69560`; доступ администратора настроен для `Anshik`.

Панель доступна по `/admin` после входа в игру. Ссылка «Админка» появляется в панели действий у администратора. Доступ требует одновременно `users.admin=1` и присутствия логина в `ADMIN_LOGINS`; обычная учётная запись не может получить данные панели через API. Назначение роли выполняется существующей командой `python -m server.admin grant-admin LOGIN` в окружении с настроенными `CRIMSON_DB` и `ADMIN_LOGINS`.

Панель показывает всех игроков без пагинации: логин, имя персонажа, дату регистрации, последнее посещение, фазу игры, клетку, ходы, здоровье, опыт и монеты. Есть поиск и фильтр «люди / боты». Бот — явная отметка администратора или тип операторского приглашения. Автоматически по логину она не назначается. Приглашение для бота создаётся командой `python -m server.admin invite-create --bot`; регистрация наследует тип приглашения, а переданный клиентом признак бота не используется. Скрипт `tools/playtest_bots.py` создаёт такие приглашения. Шесть существующих тестовых аккаунтов отмечены ботами; старый аккаунт `aanshiik` удалён по запросу владельца после резервного копирования. Текущий аккаунт выделен меткой «ВЫ», его логин указан над таблицей. Изменение отметки записывается с именем администратора и временем.

Карточка игрока содержит:

- завершённые ходы по календарным дням и график выбранной характеристики за период;
- характеристики, рюкзак, надетые предметы, игровые ограничения и состояние персонажа;
- историю команд с параметрами, игровыми сообщениями, изменениями характеристик и вещей;
- обращения игрока со сменой статуса;
- историю изменения отметки бота.

Все даты и границы периода указаны в UTC. Активность считает прирост `state.turn`, а не число HTTP-запросов или команд. Изменения характеристик на графике ступенчатые: значение сохраняется до следующего действия. Последнее посещение хранится отдельно от сессий и сохраняется после выхода.

## История и миграция

При запуске сервер добавляет таблицы `player_events`, `admin_audit` и поля `users.is_bot`, `users.last_seen`, сохраняя существующие партии. Для ранее зарегистрированного игрока создаётся одна начальная точка наблюдения. Старые команды не содержат реального времени выполнения: их игровой журнал восстанавливается из сохранённых ответов и показывается отдельно без дат. Старые ходы не распределяются искусственно по дням; графики начинаются с первой точки наблюдения. Если старые команды отсутствуют, доступен только сохранившийся журнал начальной точки.

Новые команды, изменения состояния и события записываются в одной транзакции. Повтор команды с тем же `commandId` не дублирует событие. Принятый обмен создаёт события для обоих игроков. Неуспешная команда не добавляет событие. История хранится без автоматической очистки и входит в резервную копию SQLite.

Панель читает игровые данные; из настроек сейчас меняется отметка бота. Редактирование характеристик, выдача вещей и блокировка игроков в эту версию не входят.

## Проверки

```sh
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.cjs
python tools/check_admin_headless.py
```

Последняя команда требует установленного Playwright и Chromium headless shell. Она поднимает временный локальный сервер, создаёт отдельную тестовую базу и изолированный временный headless-профиль Chromium. Пользовательские браузерные профили не используются; видимые окна не открываются. Сценарий проверяет доступ, фильтры, запись настроек и статуса обращения, графики, журнал, экранирование текста и мобильную ширину 390 px. Снимки сохраняются в `/private/tmp/crimson-admin-desktop.png` и `/private/tmp/crimson-admin-mobile.png`.
