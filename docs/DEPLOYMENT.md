# Развёртывание на VPS

Дата: 15 октября 2026. Статус: конфигурация размещения серверной игры.

Адрес: http://139.100.236.83/ . Игра работает через Gunicorn отдельной службой `crimsonworld.service` под системным пользователем `crimsonworld`. Порт 80 обслуживается напрямую. Для HTTPS понадобится домен и настройка TLS; до этого соединение идёт по HTTP.

## Файлы сервера

- `/opt/game/releases/20261015-01` — исходный выпуск игры и необходимые публичные изображения.
- `/opt/game/current` — ссылка на действующий выпуск.
- `/opt/game/venv` — отдельное Python-окружение.
- `/opt/game/data/crimsonworld.sqlite` — аккаунты, партии, чат и обратная связь. Файлы WAL/SHM в этой папке относятся к той же базе.
- `/etc/systemd/system/crimsonworld.service` — служба из `deploy/crimsonworld.service`.

Локальная база и исторические архивы не загружаются. Службы Dobby и `/opt/dobby` не участвуют в развёртывании.

## Управление

В SSH-сессии на VPS:

```sh
systemctl status crimsonworld.service
journalctl -u crimsonworld.service -n 100 --no-pager
systemctl restart crimsonworld.service
curl --fail http://127.0.0.1/health
```

Служба включена в автозапуск. Для обновления загрузить новый выпуск в отдельную папку `/opt/game/releases/`, установить зависимости при необходимости, проверить его, переключить `/opt/game/current` и перезапустить только `crimsonworld.service`. Базу из `/opt/game/data` не заменять. Перед обновлением сделать согласованную резервную копию SQLite через `sqlite3.Connection.backup()` или при остановленной игровой службе.

Один процесс Gunicorn выбран для общего ограничения частоты запросов и единого экземпляра игрового движка; четыре потока обслуживают параллельные запросы. Существующий код ограничивает регистрацию десятью игроками. Почтовая проверка адреса не настроена.
