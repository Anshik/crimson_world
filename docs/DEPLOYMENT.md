# Товилис: размещение и обслуживание

Обновлено 16 октября 2026 года. Адрес игры: https://crimsonworld.139-100-236-83.sslip.io/ . Техническое имя sslip.io указывает на IP сервера; для него настроен HTTPS через Caddy. Позднее можно заменить его собственным доменом.

## Рабочая конфигурация

- `crimsonworld.service`: Gunicorn, один процесс и четыре потока, Python 3.12, отдельный пользователь `crimsonworld`.
- Внутренний адрес приложения: `127.0.0.1:8088`; публичные порты 80/443 обслуживает Caddy. На HTTP выполняется перенаправление на HTTPS.
- `/opt/crimsonworld/current` — текущая сборка, `/opt/crimsonworld/releases/<buildId>` — выпуски, `/opt/crimsonworld/venv` — окружение.
- **База сохраняет прежний путь `/opt/game/data/crimsonworld.sqlite`**. Аккаунты и партии не пересоздаются при обновлении. Прежние `/opt/game/current` и выпуски сохранены для восстановления.
- `/etc/crimsonworld.env` — путь базы и разрешённые администраторы; файл доступен только root. Содержимое не копировать в Git и журналы.
- `/var/lib/crimsonworld/backups` — согласованные SQLite-копии. Таймер `crimsonworld-backup.timer` запускает копирование ежедневно в 03:30 по времени сервера, сохраняет 14 последних файлов. Это локальные копии на том же VPS.
- Сервисы `dobby-mcp`, `dobby-telegram` и `/opt/dobby` не меняются.

Правила выполняются сервером в QuickJS из тех же модулей JavaScript, которые использует локальная игра. Python хранит аккаунты, партии и обращения; Node.js на VPS не требуется. Клиент не отправляет готовую партию или доверенные броски. SQLite-транзакции, ревизии партий и идентификаторы команд защищают обмен и повтор запросов.

## Обновление

1. Выполнить тесты, затем `python3 tools/package_game.py /tmp/crimsonworld-release.tar.gz`. Скрипт включает только игровой интерфейс, необходимые изображения, карту и сервер. Локальная база, ключи, оригинальные архивы и промежуточные карты исключены. `build.json` фиксирует SHA-256 каждого файла.
2. Передать архив на VPS; распаковать в новый каталог `/opt/crimsonworld/releases/<buildId>`, проверить хеши. Установить зависимости из `requirements.lock` в существующее отдельное окружение.
3. Выполнить резервную копию, проверить существующие партии новым движком без записи, затем переключить `/opt/crimsonworld/current` и перезапустить только `crimsonworld.service`.
4. Проверить внутренний `/health`, публичный HTTPS, форму входа и фоновые службы. Конфигурацию базы не заменять файлами из сборки.

Конфигурации находятся в `deploy/`. Для первого запуска на другом VPS нужно заранее создать каталоги базы и системного пользователя; пути в службах должны соответствовать выбранному размещению.

## Проверки и резервные копии

В SSH-сессии:

```sh
systemctl status crimsonworld caddy crimsonworld-backup.timer
journalctl -u crimsonworld -n 60 --no-pager
curl --fail http://127.0.0.1:8088/health
curl --fail https://crimsonworld.139-100-236-83.sslip.io/health
systemctl start crimsonworld-backup.service
```

Для отката переключить ссылку на предыдущий проверенный выпуск и перезапустить игровую службу. Перед восстановлением базы остановить игровую службу, сохранить текущую базу и WAL/SHM, проверить `PRAGMA integrity_check` выбранной копии. После миграции `email` → `legacy_login` база старого выпуска совместима только с соответствующей копией кода и базы; перед восстановлением сохранить текущие данные и не смешивать схему старого выпуска с новой. Не подменять SQLite-файл при работающей игре.

## Обратная связь и администрирование

Игрок открывает «Обратная связь» в верхней панели или меню, отправляет ошибку, предложение либо вопрос по правилам. Записываются текст, версия сборки, клетка, фаза, анкета персонажа и последние три записи журнала. Email и пароль в контекст обращения не включаются. Игрок видит собственные обращения и их статус.

Оператору доступны команды (выполнять из текущей сборки, указав правильный путь базы):

```sh
cd /opt/crimsonworld/current
CRIMSON_DB=/opt/game/data/crimsonworld.sqlite /opt/crimsonworld/venv/bin/python -m server.admin feedback --detail
CRIMSON_DB=/opt/game/data/crimsonworld.sqlite /opt/crimsonworld/venv/bin/python -m server.admin status 1 in_progress
CRIMSON_DB=/opt/game/data/crimsonworld.sqlite /opt/crimsonworld/venv/bin/python -m server.admin reset-password LOGIN
```

Статусы: `open`, `in_progress`, `fixed`, `closed`. Для HTTP-администрирования имя нужно явно добавить в `ADMIN_LOGINS`, затем выполнить `grant-admin LOGIN` с той же переменной. Первый зарегистрировавшийся пользователь не становится администратором автоматически. `reset-password LOGIN` выводит одноразовый код сроком на один час; игрок сам задаёт новый пароль по этому коду.

## Регистрация и приглашения

В первой версии регистрация выполняется по одноразовому коду приглашения, имени пользователя и паролю. Email не является частью регистрации, профиля или публичного API; старое значение email сохраняется только для совместимости входа уже существующих аккаунтов. Лимит — десять аккаунтов: сейчас создано два аккаунта, свободно восемь мест. Пароли хранятся как scrypt-хеши.

Коды создаются только на сервере и выводятся оператору один раз. Уже выданные девять приглашений не пересоздавать; на текущем production-снимке одно использовано, восемь действуют, истёкших нет:

```sh
cd /opt/crimsonworld/current
CRIMSON_DB=/opt/game/data/crimsonworld.sqlite /opt/crimsonworld/venv/bin/python -m server.admin invite-create --count 9 --days 30 --label pilot
```

Оператор передаёт сырой код игроку по защищённому каналу. В SQLite хранится только SHA-256 кода; код одноразовый, имеет срок действия и может быть отозван до использования:

```sh
CRIMSON_DB=/opt/game/data/crimsonworld.sqlite /opt/crimsonworld/venv/bin/python -m server.admin invite-list
CRIMSON_DB=/opt/game/data/crimsonworld.sqlite /opt/crimsonworld/venv/bin/python -m server.admin invite-revoke INVITE_ID
```

Состояние приглашения проверяется и помечается использованным в одной транзакции. Не записывать сырые коды в журналы, Git или тикеты.

Почтовой регистрации, подтверждения адреса, восстановления через письмо и почтового отправителя в этой версии нет. Секреты почтовых провайдеров в проекте и на сервере игры не нужны.

Общие: карта Товилиса, присутствие, чат и передача вещей с подтверждением. Бои с NPC, время и поручения личные. Дуэли, совместные бои, большая карта и полноценные магические/дальнобойные умения остаются следующими этапами.

Справка по инфраструктуре: [Caddy — автоматический HTTPS](https://caddyserver.com/docs/automatic-https), [sslip.io / nip.io](https://nip.io/).
